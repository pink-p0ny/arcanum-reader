# Arcanum Reader

"Arcanum" on the home screen, "Arcanum Reader" on the App Store (bundle id `net.snobunny.arcanum`).

An iPad-first ebook reader for a self-hosted [Grimmory](https://github.com/grimmory-tools/grimmory) server.
Built with Expo (SDK 57, the version Expo Go currently supports) and the same foliate-js engine Grimmory's web reader uses, so reading positions and
highlights sync both ways with the server.

## What it does

- Signs in to your Grimmory server (JWT with automatic refresh, stored in the iOS keychain) and keeps the whole
  catalog cached in SQLite, so the library never "disappears" and works offline.
- Home tab with Continue Reading, genre shelves ranked by what you finish and rate highly, top rated and recently
  added, plus browse-by-genre chips. Library tab with search, sort and a responsive cover grid.
- Book page with description, Goodreads / Amazon / Hardcover ratings that Grimmory has synced, genres, and your
  highlights and notes for that book.
- Reader with adjustable side and top/bottom margins, text width, columns, font, size, line spacing, themes
  (light / sepia / dark / auto), paged or scrolled flow, justification and hyphenation.
- Highlights (four styles, six colors) and notes synced to Grimmory's annotation API, with an offline outbox.
- Read aloud with the device's neural voices, sentence-by-sentence highlighting, speed and voice selection.
- Surprise Me: one unread book drawn at random but weighted by your taste, with a reason and a
  "try another" button. With your own Anthropic key it asks Claude instead and takes a mood.
- Bindery integration: search Bindery's metadata providers and ask for books you do not have; an admin key
  adds and searches at once, a requester key files a request.
- A library provider interface, so Booklore, a cloud-folder library or Calibre-Web can be added as backends.
- Reading progress synced to the server (CFI + percentage) and restored on any device.
- Text selection uses the system edit menu with Highlight and Add Note in front of Translate, Search, Copy
  and Share (needs a development or store build; Expo Go shows an in-app highlight bar instead).

## Layout

```
src/app              Expo Router routes: login, (tabs)/{index,library,settings}, book/[id], read/[id]
src/components       UI: covers, shelves, reader chrome (settings sheet, TOC, highlight bar, TTS bar)
src/lib              api.ts (Grimmory REST), session.ts (auth), db.ts (SQLite), sync.ts (progress + annotations),
                     downloads.ts, library.ts, home.ts (recommendation shelves), tts.ts (read aloud)
reader-web/          The WebView reader page: vendored foliate-js + src/main.js (postMessage bridge)
assets/reader/       reader.html, the bundled page (generated by `npm run build:reader`)
scripts/             build-reader.mjs (Rollup bundle), test-reader.mjs (headless smoke test with Playwright)
```

## Development

Requirements: Node 20+, and for iOS builds either
a recent Xcode or EAS Build. Expo Go on the iPad is enough for day-to-day development.

```bash
npm install
npm start                 # also rebuilds the reader page; scan the QR code with Expo Go on the iPad
npm run typecheck
npm run lint
npm run build:reader      # after editing anything under reader-web/
npm run test:reader -- path/to/some.epub   # drives the reader page in headless Chromium
```

### Shipping to the iPad without Expo Go

```bash
npx eas-cli@latest login
npx eas-cli@latest init
npx eas-cli@latest build --profile development --platform ios   # dev client, installable from the EAS link
npx eas-cli@latest build --profile production --platform ios && npx eas-cli@latest submit -p ios  # TestFlight
```

## How sync works

- Progress: every page turn saves to SQLite immediately and is pushed to `PUT /api/v1/app/books/{id}/progress`
  (debounced). Unsynced rows are retried when the app returns to the foreground or the reader opens.
- Annotations: created locally first (negative temporary ids), then pushed to `/api/v1/annotations`; updates and
  deletes queue the same way. Server copies are refreshed when a book page or the reader opens.
- CFIs come from foliate-js, the engine Grimmory's web reader uses, so highlights made here appear there.
